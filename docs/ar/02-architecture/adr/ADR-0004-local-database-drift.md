# ADR-0004: Drift (SQLite) كقاعدة بيانات محلية

**الحالة:** مقبول

## السياق
الميزة الجوهرية الأهم بالتطبيق هي الإحصائيات التفصيلية بمستويات زمنية متعددة (ساعة/يوم/أسبوع/شهر/سنة/سنوات/فترة مخصصة). هذا يتطلب استعلامات تجميع (aggregation) معقدة ومتكررة (GROUP BY حسب تاريخ، SUM مدة، فلترة فترات متداخلة).

## القرار
اعتماد **Drift** (مبني فوق SQLite) كقاعدة البيانات المحلية الوحيدة.

## البدائل المرفوضة
- **Isar**: أسرع بعمليات القراءة/الكتابة البسيطة (NoSQL)، لكن استعلامات التجميع المعقدة (المطلوبة أساسًا لميزة الإحصائيات) أصعب وأقل كفاءة من SQL الحقيقي.
- **Hive**: مناسب لتخزين key-value بسيط، غير مناسب إطلاقًا لاستعلامات تحليلية.

## الأسباب
- SQL الحقيقي (عبر `GROUP BY`, `strftime`, إلخ) هو الأداة الطبيعية والأقوى لحساب إحصائيات زمنية متعددة المستويات.
- Type-safety كاملة بين الكود وDart عبر الكود المولَّد من Drift.
- دعم ناضج لـ migrations، مهم جدًا لأن قاعدة البيانات ستتوسع (مثلًا عند تفعيل `mode_system` لاحقًا، أو إضافة حقول جديدة).

## النتائج المترتبة
- جميع استعلامات الإحصائيات تُكتب كـ `customSelect` أو عبر Drift's query builder ضمن طبقة `data/` في ميزة `statistics`.
- راجع `docs/02-architecture/data-model.md` للـ schema الكامل.
