# الأيقونة (Adaptive Icon) والـ Splash Screen

## الأيقونة المتكيّفة (Adaptive Icon)

أندرويد (منذ النسخة 8) يتطلب أيقونة بطبقتين منفصلتين وليس صورة واحدة: `foreground` (الرمز نفسه) و`background` (لون أو نمط خلفي)، حتى يستطيع النظام قصّها بأشكال مختلفة (دائرية، مربعة، مستديرة الزوايا...) حسب واجهة الجهاز.

**أداة موصى بها:** حزمة `flutter_launcher_icons` — تولّد كل الأحجام/الكثافات المطلوبة تلقائيًا من صورتين فقط (foreground + background)، بدل تحضيرها يدويًا لكل دقة شاشة.

**نقطة تميّز بسيطة تستحق الانتباه — الأيقونة الموضوعية (Themed/Monochrome Icon):**
منذ أندرويد 13، يدعم النظام "Themed Icons" حيث يأخذ أيقونة أحادية اللون (silhouette) ويلوّنها تلقائيًا بألوان خلفية الجهاز (Material You Dynamic Color) إذا فعّل المستخدم هذا الخيار. تحضير نسخة `monochrome` بسيطة من الأيقونة إضافة صغيرة التكلفة لكنها تعطي انطباع احترافية أعلى بأجهزة حديثة.

## Splash Screen

منذ أندرويد 12، صار للنظام API رسمي لشاشة البداية (`SplashScreen API`) بدل الحلول اليدوية القديمة (شاشة مؤقتة مبنية بـ Flutter نفسه، وهي عرضة لمشاكل وميض/تأخر عرض).

**أداة موصى بها:** حزمة `flutter_native_splash` — تتعامل مع الفروقات بين أندرويد 12+ (الذي له نمط عرض وانتقال محدد من النظام) والإصدارات الأقدم تلقائيًا، وتولّد الإعدادات المطلوبة لكل منهما من صورة وألوان واحدة تُعرَّف مرة واحدة.

## ربط هذا بالهوية البصرية الموجودة

الألوان المستخدمة بالأيقونة وSplash Screen يجب أن تُستمد من نفس تعريف `AppThemeExtension` الأساسي (راجع `ui-foundation-and-conventions.md`) وليس ألوانًا منفصلة يُعاد اختراعها هنا — حتى لو كانت هذه الأصول تُولَّد خارج دورة بناء الواجهة العادية (عبر الأدوات أعلاه، وليس كـ widgets).
